# history — 历史归档

> ⚠️ **不要默认全文读取本目录。** 只有回归调查或用户明确要求追溯时，才按关键词搜索并读取命中片段。

## 约定

- 每次可验收闭环、或每个阶段写一份
- 按月分子目录：`docs/history/2026-09/`
- 文件名：`round-NN.md`（连续编号）或 `YYYY-MM-DD-标题.md`
- **写完一份就把 `NOW.md` 里对应条目删掉** —— 同一件事只留一个权威来源

## 沿用桌宠 devlog 的格式

```markdown
# 第 N 轮：标题

日期：
目标：

## 本轮交付

| 文件 | 作用 |
|---|---|
| | |

## 自检发现并修掉的问题

<!-- 这是最有价值的一节。现象 → 根因 → 修法，三列都要写。
     根因没搞清的写「疑似」，不要编。 -->

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | | | |

## 本轮数据

<!-- 断言 N/N 通过、覆盖率、耗时、体积……写数字，不写「表现良好」 -->

## 已知限制（照实记）

<!-- 没做完的、没验的、审美类无法自动判断的，全部照实写。
     不写限制的记录等于没有记录。 -->
```

## 为什么保留 devlog 风格

原母项目之前的项目（`桌宠/devlog/round-01..23.md`）用这套格式跑了 23 轮，实践有效：
**「自检发现并修掉的问题」表**迫使记录根因而不是现象，**「已知限制」节**迫使承认没做完的部分。
所以新项目沿用，只是归档位置从项目根的 `devlog/` 换成 `docs/history/`。
