# 第 4 轮：M8 新项目实战验证 —— 脚手架 + 母项目指针节

日期：2026-09-27
目标：用脚手架建**真实**新项目；验证模板的「母项目指针」节是否真的生效

## 背景

第 3 轮给 `_模板/AGENTS.md.template` 加了「母项目（规范来源与路径）」节，但当时留了限制：
**「走脚手架生成的项目」这个场景尚未实测**（第 3 轮「已知限制」第 1 条）。本轮就是来关掉它的。

## 一、先查上游规则，而不是猜

读 `@deepseek-ai/dsh-agent-instructions@0.1.2-rc.1` 的 `lib/index.js`：

- `findProjectRoot(cwd, markers)`（第 474 行）：从 cwd **向上找第一个**含 `.git` 的目录 —— 是**最近**的，不是最外层。
- `ancestorChain(root, cwd)`：链 = 「项目根 → cwd」，**只覆盖这一段**。
- `maxBytes` = **65536**（`dsh-base/cordis.patch.yml` 与各 preset 的实测值）。

**推论**：新项目一旦自带 `.git`（`新建项目.ps1` 的 `-Git` 开关会做这件事），项目根就变成新项目自己，
母项目根 `AGENTS.md` **不在链上**，而模板里那句「已自动加载，无需操作」不会跟着变 —— 是个**静默陷阱**。

本会话可以佐证：cwd = `测试项目\`（无 `.git`），注入的确实只有母项目根 `AGENTS.md`，与上述规则一致。

## 三、建真实新项目

用户拍板三件事：项目名 `规范自检工具`；`测试项目\` **保留不动**；**不用** `-Git`。

生成结果（实测）：占位符替换的文件 **3** 个（`AGENTS.md` / `PROJECT_INDEX.md` / `README.md`）、
`{{...}}` 残留 **0 处**、`AGENTS.md.template` 已还原为 `AGENTS.md`、`artifacts/` 已建、**不带** `.git`。

## 四、四场景对照实验 —— 这是本轮的核心判据

用项目自己的 `scripts/check-instructions.mjs`（内部直接调官方导出 API 取真值）：

| 场景 | 期望 | 实际 | 退出码 |
|---|---|---|---|
| A 真实新项目（不带 `.git`） | 通过 | 链含母项目根 `AGENTS.md` + 本项目 `AGENTS.md`，两份正文都在渲染文本里 | **0** |
| B `测试项目\`（空目录） | 缺项目规则 | 母项目规范在、本项目规则不在 → 部分不通过 | **1** |
| C1 夹具子目录**不带** `.git`（对照组） | 通过 | 母项目规范加载成功 | **0** |
| C2 夹具子目录**自带** `.git`（实验组） | 不通过 | 项目根被截断在该子目录，母项目规范读不到 | **1** |

C1/C2 只差一个 `.git` 目录，结论就翻转 —— 这既是**指针节生效**的正面证据，
也是**`-Git` 陷阱**的实证。回归测试 `selftest.mjs` 把三个用例固化，输出 **3/3 通过**、退出码 0。

## 五、自检发现并修掉的问题

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 脚本报 `TypeError: loadBaselineInstructionSet is not a function` | 该函数是包的**内部函数**，未从包根导出（导出名单里只有 `discoverBaselineInstructionFiles` / `loadBaselineInstructions` / `renderWorkspaceContext` 等） | 改用两个已导出 API 组合：一个拿链、一个拿渲染文本与 omitted/truncated |
| 2 | **初版判据在 C2 误报「通过」** —— 而 C2 正是负向用例 | 判据把「母项目规范」定义为「**最近** `.git` 那一层的 `AGENTS.md`」，而在自带 `.git` 的项目里那一层正是项目自己 | 改为按**最外层** `.git` 定义母项目；并把 C2 固化成 `selftest.mjs` 的负向用例 |
| 3 | `新建项目.ps1` 编辑后 BOM 再次丢失（前三字节 `23 52 65` = `#Re`） | `edit` 工具按 UTF-8 **无 BOM** 保存 | 按本文件既定程序补回，核验 `EF BB BF`、`ParserErrors: 0`。**第三次触发**，已在根 `AGENTS.md` 更新计数 |
| 4 | 回填本索引后体积涨到 **4455 B**，**超了它自己声明的 2–4 KB 上限** | 本轮往里程碑表、子项目表各加了行，**没有量体积**。这正是第 2 轮「已知限制」第 4 条说的「靠人工遵守，无自动检查」 | 重写索引压缩到 **3.9 KB 以下**；把 CRLF 虚警与触发计数移到 `README_母项目说明.md`（更该放它的地方）。**体积必须用 `Get-Item .Length` 实测，不能靠感觉** |

第 2、4 条是本轮最值钱的两条：**只跑正向用例，初版会一路「通过」到正式使用**；
**只写不改量，规则就会在自己手上破掉**。对照实验和 `Length` 实测的价值就在这。

## 七、已知限制（照实记）

1. **没有真的开一个 GUI 子项目会话去看 system-reminder**。本轮结论由
   「官方加载器对 cwd 的真实输出」+「本会话注入内容与规则一致」共同支撑，
   最后一步**人工确认还没做**。这是本轮**唯一没闭环**的一环。
2. **`-Git` 会切断自动加载**：上游代码 + 夹具实验双重确认，但**没有**在一个真实 `-Git` 项目里开过会话。
3. 检查项只实现了**检查 1**（指令链）。BOM 检测、索引体积、相对路径残留仍待做（M3/M4），
   其中「补 BOM」属写操作，**动手前必须先定干跑与备份策略**。
4. 本轮所有改动**未提交**。提交是独立授权，不因本轮结束而自动获得。
5. `测试项目\` 仍是空目录（用户决定保留不动），它作为「无 `.git` 空目录」场景保留在实验 B 里。
6. `MAX_BYTES = 65536` 是硬编码实测值，DSH 升级后可能漂移。
7. 只在 Windows + 本机 Node v24.20.0 上验证过。
