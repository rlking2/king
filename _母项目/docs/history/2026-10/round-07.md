# 第 7 轮：子项目登记自动化

日期：2026-10-01
目标：新建的项目**自动**出现在母项目记录里，不再需要人工「登记子项目」并逐项授权

## 背景（用户原话的意思）

> 「目前新建项目文件后，使项目文件读取母项目规范总不能在母项目中找到自己的索引，
> 需要你写脚本，在子项目读取规范时，自动将其添加在项目记录中」

根因有三层：

1. `新建项目.ps1` 生成项目后**不登记** —— 结尾第 4 步「把本项目登记到母项目索引」是**人工待办**。
2. 登记要**逐项授权**。`round-06` 就是一次实例：为登记 `专英汇报1`，先补骨架、再登记、再修正、
   再压缩索引，用了**4 项用户授权**、一整天的一轮。
3. 同一份项目清单**散在三处**（根 `AGENTS.md`、`PROJECT_INDEX.md`、`README_母项目说明.md`），
   各自漂移。`round-05`（修正失效目录条目）与 `round-06`（同步为实测 6 个条目）**各花一整轮**修它。

## 本轮交付

| 文件 | 变更 |
|---|---|
| `_母项目\scripts\sync-projects.mjs` | **新增** —— 同步引擎（扫描 + 幂等登记 + 干跑） |
| `_母项目\scripts\README.md` | **新增** —— 引擎说明、安全设计、已知限制 |
| `_母项目\项目清单.md` | **新增** —— 【权威】子项目清单，脚本生成，标记块 + 人工备注区 |
| `_母项目\新建项目.ps1` | 生成后**自动调用**同步引擎；「下一步 4」改为「已自动登记」 |
| `_母项目\_模板\AGENTS.md.template` | 新增「**启动自检**」节：子项目会话第一件事就是跑一次同步 |
| 根 `AGENTS.md` | 新增「子项目登记（自动）」节（含**预先授权**例外）；目录树改为指向清单；BOM 计数三→四 |
| `_母项目\PROJECT_INDEX.md` | 子项目表 → 一行链接（**同时缓解 4 KB 压力**）；专题文档补两行 |
| `_母项目\README_母项目说明.md` | 目录树改为指向清单 |
| `规范自检工具\AGENTS.md` | 修正过宽的「只读母项目」安全边界 + 清掉已失效的项目名单 |

## 一、关键设计：为什么只写一个文件

写操作碰自动加载的 `AGENTS.md` **风险不对称** —— 那文件一坏，所有会话（含母项目自己）都读不到规范。
所以引擎**只写 `_母项目\项目清单.md`**，并在其中只改标记块：

```
<!-- BEGIN AUTO: projects -->   ← 引擎只改这一段之间
<!-- END AUTO: projects -->
```

块外的「人工备注」节一律不动。标记缺失或重复时**拒绝写入**并退出 `1`（不猜、不自动修）。
另加：**写后立即重读核验**，标记仍在且文件没被写坏才算成功。

## 二、预先授权（必须显式，否则机制自相矛盾）

子项目的 `AGENTS.md` 一般写着「只读母项目」。若不开口子，这个机制在子项目里**会被自己的规则禁止**。
故在根 `AGENTS.md` 写明例外，边界五条：只写一个文件、只改标记块、不碰任何其它文件、幂等、
可回退（清单在版本库里）。**只覆盖「登记」这一件事** —— 提交/推送/删除/覆盖仍各自需要授权。

## 三、四处触发（覆盖所有路径）

| 触发 | 覆盖场景 |
|---|---|
| `新建项目.ps1` 自动调用 | 走脚手架建的项目 |
| 模板 `AGENTS.md` 的「启动自检」 | 建的时候脚本没跑成、或事后目录被改 |
| 手工命令 | 任何其它时候 |
| （幂等） | 上面三处重复跑都无害 |

## 自检发现并修掉的问题

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 编辑 `新建项目.ps1` 后 BOM 第四次丢失（`EF BB BF` → `23 52 65`） | `edit` 工具按 UTF-8 无 BOM 保存 | 按既定程序补回并核验 `ParserErrors: 0`；根 `AGENTS.md` 计数三→四 |
| 2 | `规范自检工具\AGENTS.md` 的安全边界会**禁止本机制** | 原文写「绝不写入 `_母项目\` … 除非用户当轮明确要求」，作用域过宽（`round-04` 审计已记，本轮才必须处理） | 限定为「本工具运行期与在本项目目录内的工作」，并写明登记例外；同时清掉已失效的 `测试项目\`、`王国保卫战…` 名单 |
| 3 | `README_母项目说明.md` 也有一份项目树 | 同源漂移问题 | 一并改为指向 `项目清单.md` |

## 本轮数据（全部实测）

- **正向**：跑 `新建项目.ps1 -Name "_登记自检"` → 引擎自动触发 → `_登记自检/` **即时出现**在清单里
- **反向**：删掉 `_登记自检/` 后跑同步 → 清单**自动移除**该行，无残留
- **幂等**：同一状态连跑两次，第二次报「**无变化（幂等）**」
- **干跑**：`--dry-run` 只打印拟写入内容与字节变化（`1319 → 2694 B`），不落盘
- **扫描准确性**：`专英汇报1/` 判定 ⚠️ 待填（`- 待填写`×4）；`桌宠/` 判定 ❌ 有 `.git` 被截断；
  `信号与系统/`、`信号与系统实验/` 判定 ❌ 未走脚手架 —— 与人工核验一致
- 自检产物 `_登记自检/` 验证后**已移除**（本轮创建，非用户资产）

## 已知限制（照实记）

1. **只扫工作区根的直接子目录**，不递归；嵌套更深的项目发现不了。
2. **「规范化」是启发式**：靠正则找 `{{占位符}}` / `（待填写）` / `- 待填写`。换了写法会误判（偏乐观）。
3. **不建 Obsidian 项目页**。跨项目记忆缺页时，清单只记录，不去动 vault。
4. **`最后修改` 深度限 3 层**且跳过 `node_modules` / `.git`，深层改动可能不反映。
5. **未验证「在子项目会话里跑启动自检」**：模板那节是本轮新加的，还没在真实子项目会话里实际执行过。
   本轮验证的是引擎本身 + 脚手架自动触发，**「AI 照做」这一环仍属未闭环**。
6. **`.gitignore` 未处理 `_母项目\artifacts\`**：它在反向放行目录之下，将来放非空文件会被跟踪
   （`round-06` 已记，本轮仍未做，属新授权）。本轮新增的 `scripts\`、`项目清单.md` 在 `_母项目\` 内，
   **会被正常跟踪**，符合预期。
7. 全部**未提交**。提交是独立授权。
