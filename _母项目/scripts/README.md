# scripts — 母项目脚本

## `sync-projects.mjs` —— 子项目登记同步引擎

把「新建的项目在母项目记录里找不到自己」这件事变成**自动、幂等**的一步。

### 干什么

扫描工作区根下的每个目录，现场采集事实，写进 `_母项目\项目清单.md` 的标记块：

| 列 | 判据 |
|---|---|
| 规范化 | `AGENTS.md` 存在且无待填占位 = 已填实；有占位 = 待填；无 = 未走脚手架 |
| 母项目规范自动加载 | 无 `.git` = ✅；有 `.git` = ❌ 被截断（见 `docs/history/2026-09/round-04.md`） |
| 上下文文件 | `docs/context/` 下 NOW/MAP/RUNBOOK/DECISIONS/RISKS 的现有数量 |
| 条目 / 最后修改 | 目录直接子项数；子项最新 mtime（深度 ≤3，跳过 `node_modules` 与 `.git`） |

### 用法

```powershell
node _母项目\scripts\sync-projects.mjs              # 同步（幂等）
node _母项目\scripts\sync-projects.mjs --dry-run    # 只打印，不落盘
node _母项目\scripts\sync-projects.mjs --quiet      # 只在有变化时输出
```

退出码：`0` = 同步完成（**无论有没有变化**）；`1` = 失败（清单不存在、标记不合法、写后核验不过）。

### 三处自动触发

| 触发 | 机制 |
|---|---|
| 建新项目 | `新建项目.ps1` 生成完**自动调用**（失败只告警，不回滚已生成的项目） |
| 在子项目里开会话 | 项目 `AGENTS.md`（自动加载）的「启动自检」节会让人先跑一次 |
| 手工 | 上面那条命令，随时可跑 |

### 安全设计（这是它敢自动写的原因）

1. **只写一个文件** —— `_母项目\项目清单.md`。**不碰**自动加载的 `AGENTS.md`：
   那文件一坏，所有会话都读不到规范，风险不对称。
2. **只改标记块** —— `<!-- BEGIN AUTO: projects -->` 与 `<!-- END AUTO: projects -->` 之间的内容。
   块外的人写文字（「人工备注」节）**一律不动**。
3. **标记不合法就拒绝写入** —— 标记缺失或重复时退出 `1`，不猜、不自动修。
4. **幂等** —— 内容没变就不写。可随便重复跑。
5. **写后核验** —— 写完重读，确认标记仍在、文件没被写坏；不过就报错，不静默。
6. **可回退** —— 清单在版本库里，`git diff` 可查、`git log` 可溯。

### 已知限制

1. **只扫工作区根的直接子目录**，不递归。嵌套更深的项目不会被发现。
2. **「规范化」是启发式**，靠正则找 `{{占位符}}` / `（待填写）` / `- 待填写`。
   换了占位写法就会误判（表现为「已填实」，偏乐观）。
3. **不建 Obsidian 项目页**。跨项目记忆里缺页时，脚本只在清单里体现，不去动 vault。
4. **`最后修改` 深度限 3 层**，且跳过 `node_modules` 与 `.git` —— 深层的改动可能反映不出来。
5. **不判定两个 `.git` 的嵌套仓库场景**：它只按「本目录有没有 `.git`」判，
   这和 DSH 的 `findProjectRoot`（取**最近**的 `.git`）一致，但没验证过更深的嵌套。
